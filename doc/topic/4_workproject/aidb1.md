### Описание базы данных PostgreSQL

#### Общая архитектура

База данных разработана на платформе PostgreSQL и состоит из четырёх взаимосвязанных таблиц, обеспечивающих хранение и обработку данных веб‑приложения для учёта питания и расчёта КБЖУ. Структура оптимизирована для быстрого доступа к данным, целостности связей и масштабируемости.

#### Описание таблиц

**1. Таблица `users`**

Хранит регистрационные данные пользователей.

**Поля:**
* `id` (SERIAL PRIMARY KEY) — уникальный идентификатор пользователя (автоинкремент);
* `username` (VARCHAR(50) UNIQUE NOT NULL) — логин пользователя, должен быть уникальным;
* `email` (VARCHAR(100) UNIQUE NOT NULL) — email пользователя, уникальный адрес;
* `password_hash` (VARCHAR(255) NOT NULL) — хешированный пароль (с использованием Werkzeug);
* `created_at` (TIMESTAMP DEFAULT CURRENT_TIMESTAMP) — дата и время регистрации пользователя;
* `is_active` (BOOLEAN DEFAULT TRUE) — флаг активности аккаунта.

**Ограничения:**
* уникальность `username` и `email`;
* обязательное заполнение полей `username`, `email`, `password_hash`.

---

**2. Таблица `products`**

Содержит общую базу продуктов с пищевой ценностью, доступную всем пользователям.

**Поля:**
* `id` (SERIAL PRIMARY KEY) — уникальный идентификатор продукта (автоинкремент);
* `name` (VARCHAR(200) NOT NULL) — название продукта;
* `calories` (DECIMAL(8,2) NOT NULL) — калории на 100 г продукта;
* `proteins` (DECIMAL(8,2) NOT NULL) — белки на 100 г (г);
* `fats` (DECIMAL(8,2) NOT NULL) — жиры на 100 г (г);
* `carbs` (DECIMAL(8,2) NOT NULL) — углеводы на 100 г (г);
* `category` (VARCHAR(100)) — категория продукта (овощи, фрукты, мясо и т. д.);
* `is_custom` (BOOLEAN DEFAULT FALSE) — флаг пользовательского продукта;
* `created_by` (INTEGER REFERENCES users(id)) — ID пользователя, добавившего продукт (NULL для стандартных);
* `created_at` (TIMESTAMP DEFAULT CURRENT_TIMESTAMP) — дата добавления продукта.

**Индексы:**
* индекс по полю `name` для ускорения поиска продуктов;
* индекс по `category` для фильтрации по категориям.

---

**3. Таблица `food_entries`**

Фиксирует личные записи о потреблённой пище каждого пользователя.

**Поля:**
* `id` (SERIAL PRIMARY KEY) — уникальный идентификатор записи;
* `user_id` (INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE) — ссылка на пользователя (связь с `users`);
* `product_id` (INTEGER NOT NULL REFERENCES products(id)) — ссылка на продукт (связь с `products`);
* `quantity` (DECIMAL(8,2) NOT NULL) — количество продукта в граммах;
* `meal_type` (VARCHAR(20) NOT NULL) — тип приёма пищи: «завтрак», «обед», «ужин», «перекус»;
* `consumed_date` (DATE NOT NULL) — дата потребления (по умолчанию — текущая дата);
* `created_at` (TIMESTAMP DEFAULT CURRENT_TIMESTAMP) — время создания записи.

**Связи:**
* внешний ключ `user_id` ссылается на `users.id` с каскадным удалением (при удалении пользователя удаляются его записи);
* внешний ключ `product_id` ссылается на `products.id`.

**Индексы:**
* составной индекс по `(user_id, consumed_date)` для быстрого получения дневных записей пользователя.

---

**4. Таблица `user_profile`**

Хранит персональные профили и настройки пользователей.

**Поля:**
* `id` (SERIAL PRIMARY KEY) — уникальный идентификатор профиля;
* `user_id` (INTEGER UNIQUE NOT NULL REFERENCES users(id) ON DELETE CASCADE) — ссылка на пользователя (связь один‑к‑одному с `users`);
* `height` (DECIMAL(5,2)) — рост пользователя в см;
* `weight` (DECIMAL(5,2)) — текущий вес пользователя в кг;
* `age` (INTEGER) — возраст пользователя;
* `gender` (VARCHAR(10)) — пол: «мужской», «женский»;
* `activity_level` (DECIMAL(3,2) DEFAULT 1.2) — коэффициент активности (1.2–1.9);
* `target_calories` (INTEGER) — целевая норма калорий в день;
* `target_proteins` (DECIMAL(6,2)) — целевые белки (г/день);
* `target_fats` (DECIMAL(6,2)) — целевые жиры (г/день);
* `target_carbs` (DECIMAL(6,2)) — целевые углеводы (г/день);
* `weight_goal` (DECIMAL(5,2)) — целевой вес (кг);
* `updated_at` (TIMESTAMP DEFAULT CURRENT_TIMESTAMP) — дата последнего обновления профиля.

**Связи:**
* внешний ключ `user_id` ссылается на `users.id` с каскадным удалением.

#### Связи между таблицами

1. **users → food_entries** (один‑ко‑многим): один пользователь может иметь множество записей о потреблённой пище.
2. **products → food_entries** (один‑ко‑многим): один продукт может упоминаться во множестве записей разных пользователей.
3. **users → user_profile** (один‑к‑одному): у каждого пользователя есть ровно один профиль.
4. **users → products** (один‑ко‑многим, опционально): пользователь может добавлять собственные продукты (поле `created_by`).

#### Нормализация и целостность данных

База данных приведена к третьей нормальной форме (3NF):
* устранены повторяющиеся группы;
* все неключевые поля зависят только от первичного ключа;
* отсутствуют транзитивные зависимости.

**Меры обеспечения целостности:**
* внешние ключи с каскадными операциями (ON DELETE CASCADE);
* уникальные ограничения на логины и email;
* NOT NULL для обязательных полей;
* индексы для ускорения запросов по ключевым полям.

#### Оптимизация и производительность

Для повышения производительности реализованы:
* индексы по полям, используемым в фильтрах и сортировках (`products.name`, `products.category`, `food_entries.user_id`, `food_entries.consumed_date`);
* использование DECIMAL для точных расчётов КБЖУ (без ошибок округления);
* разделение данных на логические таблицы для минимизации дублирования.

#### Заключение

Разработанная структура базы данных PostgreSQL обеспечивает:
* надёжное хранение пользовательских данных и информации о питании;
* быстрый доступ к записям за счёт индексирования;
* целостность связей между сущностями;
* масштабируемость для добавления новых функций (например, рецептов, тренировок);
* точность расчётов КБЖУ благодаря использованию типа DECIMAL.

Такая архитектура соответствует требованиям проекта и готова к интеграции с бэкендом на Flask.
